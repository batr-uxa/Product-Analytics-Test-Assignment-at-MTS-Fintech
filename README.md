# Задача 1: АБ-тест баннера

## Условие
В МТС банке запустили аб-тест на странице, где можно оформить заявку на банковскую карту. 
В варианте А из 2574 клиентов, зашедших на страницу, на баннер нажали 350, в варианте Б из 2855 нажали 375. 
Какой вариант баннера предложить продакту и почему?

## Расчет конверсии
- Вариант А: 350 / 2574 = **13.60%**
- Вариант Б: 375 / 2855 = **13.13%**

На первый взгляд, вариант А лучше, так как конверсия выше на 0.47 п.п.

## Проверка статистической значимости
Чтобы понять, не является ли эта разница случайной, я провел Z-тест для пропорций.

**Гипотезы:**
- H0: Конверсии равны (p_A = p_B)
- H1: Конверсии различаются (p_A ≠ p_B)

**Результат Z-теста:**
- Z-статистика: **0.51**
- Критическое значение для 95% доверия: **1.96**

Так как |Z| = 0.51 < 1.96, мы **не отвергаем нулевую гипотезу**. Разница между вариантами статистически не значима.

## Вывод для продакта
Я бы **не рекомендовал** менять текущий баннер (или выбирать вариант Б) на основе этих данных, так как разница может быть случайной.

## 📌 Задача 2:
Есть таблица `transact` с транзакциями клиентов, начиная с 2021 года. 
Столбцы таблицы:
*   `id_client` — ID клиента
*   `tran_time` — время транзакции
*   `id_tran` — ID транзакции
*   `sum_tran` — сумма транзакции

**Необходимо решить две подзадачи:**
1.  Посчитать траты каждого клиента за последние 30 дней от текущего числа.
2.  Для топ-100 наиболее платежеспособных клиентов за всю историю покупок посчитать траты помесячно.

## Алгоритм решения (Логика)

### Подзадача 1: Траты за последние 30 дней
**Бизнес-логика:** Нам нужны только те транзакции, которые произошли недавно. «Последние 30 дней от текущего числа» означает, что мы берем текущую дату (`CURRENT_DATE`) и отнимаем от неё 30 дней.

**Шаги алгоритма:**
1.  Отфильтровать таблицу `transact` по условию: `tran_time >= CURRENT_DATE - INTERVAL '30 days'`.
2.  Сгруппировать оставшиеся записи по `id_client`.
3.  Просуммировать столбец `sum_tran` для каждого клиента.

### Подзадача 2: Топ-100 клиентов и их помесячные траты
**Бизнес-логика:** Это задача из двух шагов. Сначала нам нужно понять, кто самые «жирные» клиенты за всё время, а потом посмотреть на их траты в разрезе месяцев.

**Шаги алгоритма:**
1.  **Поиск топ-100:** Сгруппировать всю таблицу по `id_client`, просуммировать `sum_tran`, отсортировать по убыванию суммы и взять первые 100 записей.
2.  **Помесячная разбивка:** Взять исходную таблицу и «приджойнить» её к нашему списку топ-100 (чтобы отсеять остальных клиентов).
3.  Сгруппировать результат по `id_client` и месяцу транзакции (используя `DATE_TRUNC('month', tran_time)`).
4.  Просуммировать траты внутри каждой группы.
